# Σχεδιασμός και Ανάπτυξη Εφαρμογών Κινητού Υπολογισμού 2026-27

# Εκφώνηση Project (ατομική ή ομάδα 2 ατόμων)

## PowerAlert: Ανάπτυξη εφαρμογής ενημέρωσης και ειδοποίησης για προγραμματισμένες διακοπές ηλεκτροδότησης

### Εισαγωγή

Οι προγραμματισμένες διακοπές ηλεκτροδότησης μπορούν να επηρεάσουν την καθημερινότητα των πολιτών, τη λειτουργία επιχειρήσεων και τον προγραμματισμό εργασιών. Ο ΔΕΔΔΗΕ δημοσιεύει τις σχετικές ανακοινώσεις στην ιστοσελίδα [Προγραμματισμένες Διακοπές Ηλεκτροδότησης](https://siteapps.deddie.gr/outages2public), όπου ο επισκέπτης επιλέγει νομό και δήμο/κοινότητα για να ενημερωθεί για τις περιοχές και τις ώρες των διακοπών.

Σκοπός του project είναι η ανάπτυξη εφαρμογής για smartphones, μέσω της οποίας ο χρήστης θα μπορεί να ενημερώνεται για τις προγραμματισμένες διακοπές, να δημιουργεί προσωπικό προφίλ και να αποθηκεύει περιοχές που τον ενδιαφέρουν, όπως η κατοικία, το εξοχικό ή ο χώρος εργασίας του. Το σύστημα θα ελέγχει περιοδικά την πηγή δεδομένων και, όταν εντοπίζει προγραμματισμένη διακοπή που αντιστοιχεί σε περιοχή ενδιαφέροντος του χρήστη, θα του αποστέλλει αυτόματα ειδοποίηση (notification).

Η εφαρμογή αφορά τις προγραμματισμένες διακοπές που δημοσιεύονται στη συγκεκριμένη πηγή.

### Απαιτήσεις smartphone app

Οι παρακάτω απαιτήσεις αποτελούν τον βασικό κορμό του project χωρίς να αποκλείουν επιπλέον που μπορεί να οριστούν από εσάς.

1. **Αρχική οθόνη με χάρτη.** Εμφάνιση χάρτη της Ελλάδας, προσβάσιμου χωρίς σύνδεση σε λογαριασμό, με δυνατότητα επιλογής νομού. Με την επιλογή ενός νομού θα εμφανίζεται λίστα με τις τρέχουσες και μελλοντικές προγραμματισμένες διακοπές που έχουν ανακτηθεί για αυτόν. Οι νομοί με διαθέσιμες προγραμματισμένες διακοπές να επισημαίνονται με διαφορετικό χρώμα. Κάτω από τον χάρτη να εμφανίζεται επεξήγηση των χρωμάτων.  
     
2. **Δημιουργία λογαριασμού και προσωπικού προφίλ.** Εγγραφή και είσοδος μέσω ενός παρόχου ταυτοποίησης, όπως Google ή Facebook. Δεν απαιτείται υποστήριξη και των δύο. Ο χρήστης να μπορεί να βλέπει τα βασικά στοιχεία του προφίλ του και να αποσυνδέεται. Η σύνδεση να διατηρείται με ασφαλή τρόπο για διάστημα ημερών από την τελευταία χρήση.  
     
3. **Καταχώριση περιοχών ενδιαφέροντος.** Ο συνδεδεμένος χρήστης να μπορεί να αποθηκεύει μία ή περισσότερες περιοχές μέσω κατάλληλης φόρμας. Κάθε καταχώριση να περιλαμβάνει προσωπική ονομασία, π.χ. «Κατοικία», «Εξοχικό» ή «Εργασία», νομό και (προαιρετικά) δήμο/κοινότητα. Οι επιλογές νομού και (προαιρετικά) δήμου/κοινότητας να συμφωνούν με τις ονομασίες της πηγής δεδομένων (ιστοσελίδα ΔΕΔΔΗΕ).  
     
4. **Διαχείριση περιοχών ενδιαφέροντος.** Δυνατότητα προβολής, επεξεργασίας και διαγραφής των αποθηκευμένων περιοχών, καθώς και ενεργοποίησης ή απενεργοποίησης των ειδοποιήσεων για κάθε περιοχή ξεχωριστά. Να παρέχεται επίσης συγκεντρωτική λίστα των διακοπών που αντιστοιχούν στις ενεργές περιοχές ενδιαφέροντος.  
     
5. **Περιοδική ανάκτηση και αντιστοίχιση.** Το σύστημα να ελέγχει αυτόματα την πηγή δεδομένων σε τεκμηριωμένο χρονικό διάστημα, ενδεικτικά ανά 60 λεπτά, και να ενημερώνει την κεντρική ΒΔ. Με την προσθήκη ή αλλαγή μιας περιοχής να ελέγχονται και οι ήδη διαθέσιμες διακοπές που δεν έχουν ολοκληρωθεί.   
   **Επισήμανση για υπεύθυνη χρήση της υπηρεσίας ΔΕΔΔΗΕ:** Η ανάκτηση δεδομένων πρέπει να γίνεται με τρόπο που να μην επιβαρύνει υπερβολικά την υπηρεσία. Να αποφεύγονται τα συνεχή, μαζικά ή ταυτόχρονα αιτήματα και να επαναχρησιμοποιούνται τα δεδομένα που έχουν ήδη αποθηκευτεί στην δική σας κεντρική ΒΔ. Η προβολή ή ανανέωση μιας οθόνης από τον χρήστη δεν πρέπει να προκαλεί κάθε φορά νέο αίτημα προς τον ΔΕΔΔΗΕ.  
     
6. **Αυτόματες ειδοποιήσεις.** Όταν εντοπίζεται για πρώτη φορά μια σχετική διακοπή για τον συγκεκριμένο χρήστη, να αποστέλλεται ειδοποίηση στο κινητό του, εφόσον οι ειδοποιήσεις είναι ενεργές και έχει δοθεί η απαιτούμενη άδεια από το λειτουργικό σύστημα. Η ειδοποίηση να περιλαμβάνει την περιοχή ενδιαφέροντος και το χρονικό διάστημα της διακοπής. Με το πάτημά της να ανοίγει η αντίστοιχη οθόνη λεπτομερειών.  
     
7. **Αποφυγή επαναλαμβανόμενων ειδοποιήσεων.** Η ίδια ανακοίνωση να μην προκαλεί νέα ειδοποίηση σε κάθε περιοδικό έλεγχο. Αν αντιστοιχεί σε περισσότερες από μία περιοχές του ίδιου χρήστη, να δημιουργείται μία ειδοποίηση που να αναφέρει τις σχετικές περιοχές.  
     
8. **Ενημέρωση και χειρισμός σφαλμάτων.** Να εμφανίζονται ο χρόνος τελευταίας επιτυχούς ενημέρωσης από την πηγή. Σε αποτυχία ελέγχου να διατηρούνται τα τελευταία διαθέσιμα δεδομένα με ένδειξη ότι δεν είναι πρόσφατα αν έχει περάσει ένα ικανό διάστημα που θα ορίσετε εσείς.  
     
9. **Κεντρική βάση δεδομένων.** Απαιτείται κεντρική, απομακρυσμένη ΒΔ, δηλαδή εκτός κινητού. Αυτή να αποθηκεύει τις πληροφορίες που προκύπτουν από τις παραπάνω λειτουργίες, όπως χρήστες, περιοχές ενδιαφέροντος, ανακτημένες διακοπές, ρυθμίσεις και ιστορικό ειδοποιήσεων.

### Τεχνολογίες \- Εργαλεία

Για την υλοποίηση της εφαρμογής smartphone μπορείτε να χρησιμοποιήσετε έναν από τους παρακάτω τρόπους:

1. Android Studio για native εφαρμογή Android (Java/Kotlin).  
2. Xcode για native εφαρμογή iOS (Swift/Objective-C).  
3. Ανάπτυξη με υβριδικό πλαίσιο (Flutter, React Native, Ionic, κοκ).

Για την αποθήκευση δεδομένων και την ταυτοποίηση χρηστών προτείνεται η αξιοποίηση διαχειριζόμενων υπηρεσιών νέφους, όπως το **Google Firebase**, με χρήση:

* Cloud Firestore για την αποθήκευση των δεδομένων.  
* Firebase Authentication για την εγγραφή και τη σύνδεση χρηστών.  
* Κανόνων ασφαλείας (Security Rules) για τον έλεγχο πρόσβασης, ώστε κάθε χρήστης να έχει πρόσβαση μόνο στα προσωπικά δεδομένα που του αναλογούν.

Επιτρέπεται η χρήση άλλης απομακρυσμένης βάσης δεδομένων, πχ MySQL, εφόσον υλοποιηθούν οι απαιτούμενες λειτουργίες.

Η εφαρμογή smartphone πρέπει να διαλειτουργεί με τις κεντρικές υπηρεσίες και τη ΒΔ. Η ιδιωτική πληροφορία των χρηστών να προστατεύεται με έλεγχο πρόσβασης στην πλευρά του εξυπηρετητή ή με κατάλληλους κανόνες ασφάλειας της υπηρεσίας νέφους.

### Ζητούμενα

Η εφαρμογή πρέπει να υλοποιεί τη λειτουργικότητα που περιγράφεται στην ενότητα «Απαιτήσεις», χρησιμοποιώντας τα εργαλεία και τις τεχνολογίες που αναφέρονται. Μπορείτε να σχεδιάσετε τη διεπαφή χρήστη σύμφωνα με τη δική σας αισθητική και εμπειρία, αλλά με σαφή πλοήγηση και ευανάγνωστη παρουσίαση των πληροφοριών.

Η παράδοση θα γίνει μέσα από το αποθετήριο GitHub όπου θα φροντίζετε να ανεβάζετε τα αρχεία του πηγαίου κώδικα και της εφαρμογής σταδιακά, καθόλη την διάρκεια υλοποίησης.

Παραδοτέα του project είναι:

1. **Ο πηγαίος κώδικας** της εφαρμογής στο GitHub  
2. **Ένα αρχείο αναφοράς DOC/DOCX ή PDF ή Markdown**, που να περιλαμβάνει:  
   - Λειτουργικές και μη λειτουργικές απαιτήσεις και UML διαγράμματα περιπτώσεων χρήσης.  
   - Σύντομη περιγραφή του τρόπου υλοποίησης των προδιαγραφών.  
   - Μοντέλο δεδομένων: Διάγραμμα ER για σχεσιακή ΒΔ ή περιγραφή συλλογών, εγγράφων και συσχετίσεων για NoSQL.  
   - Περιγραφή της αρχιτεκτονικής, της ανάκτησης δεδομένων, του κανόνα αντιστοίχισης περιοχών, του περιοδικού ελέγχου και της αποφυγής επαναλαμβανόμενων ειδοποιήσεων.  
   - Τις τεχνολογίες και τα εργαλεία που χρησιμοποιήθηκαν, οδηγίες εγκατάστασης και εκτέλεσης, καθώς και τους περιορισμούς της υλοποίησης.

   

3. **Ένα βίντεο διάρκειας 3–5 λεπτών** που να επιδεικνύει τη λειτουργικότητα σε κινητή συσκευή: περιήγηση στον χάρτη, προβολή διακοπών, σύνδεση, διαχείριση περιοχών, αυτόματη ειδοποίηση στο παρασκήνιο και άνοιγμα των λεπτομερειών της. Να επιδεικνύονται και οι αλλαγές στη ΒΔ. Αναρτήστε το βίντεο σε αποθετήριο προσβάσιμο στους διδάσκοντες, π.χ. YouTube με πρόσβαση μέσω συνδέσμου, και προσθέστε τον σύνδεσμο στο README του αποθετηρίου σας.  
     
4. **Προφορική εξέταση**, με παρουσία όλων των μελών της ομάδας, διάρκειας περίπου 20 λεπτών, σε ημέρα και ώρα που θα ανακοινωθεί. Στην προφορική εξέταση θα αξιολογηθεί ο βαθμός κατανόησης των τεχνολογιών και εργαλείων που χρησιμοποιήσατε.

Όλα τα παραπάνω παραδοτέα είναι υποχρεωτικά για την τελική αξιολόγηση του project.

Η υλοποίηση του project έχει βαρύτητα **40% επί της συνολικής βαθμολογίας του μαθήματος**.

#### Πολιτική χρήσης Παραγωγικής ΤΝ (GenAI)

Η εργασία έχει πολιτική χρήσης εργαλείων GenAI επιπέδου 4, δηλαδή «Παραγωγή μέρους περιεχομένου με ρητή δήλωση». Μπορείτε να χρησιμοποιείτε παραγωγή μέρους του κώδικα μέσω GenAI με την προϋπόθεση χρήσης ως βοηθό μάθησης και κατανόησης των εργαλείων και όχι ως «έτοιμη λύση».  
**Υποχρεωτική** είναι η καταγραφή και επισύναψη log χρήσης (εργαλείο/ημερομηνία/σκοπός/τι αξιοποιήθηκε) καθώς και διαμοιρασμός διαλόγων (prompts) με τα εργαλεία.
